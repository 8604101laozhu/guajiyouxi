# 选型：置顶开关（是否保持游戏条在最上层）

用户要求：**加一个开关，是否保持游戏页面在最上一层**。

## 先查现成方案（规矩：动手前先对比）

| 方案 | 说明 | 判定 |
| --- | --- | --- |
| 一直置顶，不做开关 | 现在的状态 | ✗ 用户明确要开关（看视频/全屏演示时条形碍事） |
| 只留全局快捷键 `Ctrl+Alt+T` | 已有 | ✗ 光有快捷键，**看不见当前是开还是关**（用户上次的问题就是"不明显"） |
| 第三方库（`electron-window-state` + 各种 topmost 助手） | 存位置 + 置顶 | ✗ 只为存两个字段引依赖；且 topmost 保持这事没人做得比"自己写 40 行"更靠谱 |
| **可见按钮 + 快捷键 + 记忆 + 心跳保持**（采用） | 见下 | ✔ |

## 从 GitHub / 官方 issue 抄到的四条

1. **`setAlwaysOnTop(flag, level)` 的 level 只有 macOS 认**（`"screen-saver"` 能盖住全屏应用），Windows/Linux 会忽略它。
   据 [electron#10078](https://github.com/electron/electron/issues/10078)（32★，MarshallOfSound 回复）：**任何平台都盖不住别的全屏应用**，
   那是 OS 设计（macOS 上连纯原生应用也不行，HSTracker 那种要靠私有手段）。所以别承诺"永远盖住全屏游戏"。
2. **topmost 会被别的 topmost 窗口顶掉，Electron 不会自己恢复** —— 桌面挂件/悬浮窗类应用的通行做法是定期重新确认。
   但**无脑重设会闪烁/抢焦点**，所以抄「**check-then-fix**」：每 2 秒看一次，只在真的丢了时才调一次 `setAlwaysOnTop`。
   落地在 `electron/ontop.cjs` 的 `ensure()`，配 `isAlwaysOnTop()` 短路。
3. **[electron#5124](https://github.com/electron/electron/issues/5124)：`alwaysOnTop` 和透明窗口有交互**（有人一开置顶透明就全没了）。
   这条对这个工程特别危险（我们整个条就是靠透明活着的），所以：**开关动过之后必须重新验透明**。
   → 自检里带像素级 alpha 对比（开关前后两带 alpha 必须一致，容差 ±8）。实测 170.0/167.9 前后完全一致。
4. **偏好要落盘**：用户关掉过就下次别再自作主张打开。复用已有的窗口状态文件
   `%APPDATA%\guajiyouxi\desk-window.json`（本来就存位置），加一个 `alwaysOnTop` 字段，**写入时保留其它字段**。

## 落地

| 部分 | 文件 | 说明 |
| --- | --- | --- |
| 保持器 + 偏好读写（纯逻辑，可单测） | `electron/ontop.cjs` | `createOnTopKeeper`（注入 window + 定时器）、`readOnTopPref` / `writeOnTopPref`（注入 fs） |
| 唯一入口 | `electron/main.cjs` 的 `setOnTop(on, why)` | 界面点击 / `Ctrl+Alt+T` / 自检**都走这一条路**：应用 → 落盘 → 广播三件事一起发生 |
| 遥控器（可见开关） | `electron/preload.cjs` + `src/app/desk/on-top-chip.tsx` | 右上角按钮「📌 置顶：开 / 置顶：关」，跟随主进程广播；纯浏览器里不显示 |
| 启动 | `createWindow` | 初始值直接取记忆（不是先开再关，避免启动闪一下） |

**为什么按钮放右上角 DOM 而不是画在 canvas 里**：canvas 里的可点区域要往纯 TS 内核里塞 UI 命中测试，
破坏"内核只放游戏、壳只管窗口"的分工；DOM 按钮一行 `onClick` 就够，且不干扰 canvas 上的拖动（拖动的 pointerdown 只绑在 canvas 上）。

**已知限制**：点击穿透开着时（`Ctrl+Alt+D`）鼠标事件到不了页面，按钮点不动 —— 所以 `Ctrl+Alt+T` 是永远可用的那条路。
盖不住别人的全屏应用（见第 1 条）。

## 自检

```bash
DESK_ONTOP_CHECK=1 npm run desk
```

真机实测（`electron/main.cjs` 的 `DESK_ONTOP_CHECK` 块，走的是界面同一条 IPC 路径）：

```
置顶开关：初始 开 → 关（IPC 返回 false，实际 关）→ 开（实际 开）
透明对比：关之前 天空 170.0 地面 167.9 / 关之后 天空 170.0 地面 167.9（允许 ±8）
偏好落盘：关掉后文件里 alwaysOnTop=false；被顶掉 1399ms 后自己补回来=true
界面按钮：「📌 置顶：开」→「置顶：关」→「📌 置顶：开」
置顶开关自检：通过
```

七条判据：按记忆启动 / 关得掉 / 开得回 / **按钮跟着翻** / 偏好落盘 / **关了透明没坏** / **被顶掉能自己补回**。
自检结束会把用户的偏好还原（别让一次冒烟改了人家记住的设置）。
