# 战斗舞台：固定舞台（英雄守桩，怪从右边走进来）

用户要求：「保持人物和怪在画面中间相遇，怪物从右边走向人物」。

## 改之前是什么样

英雄**一路向右推图**（`ai.ts` 的 `advance`），怪在**英雄前方 380px** 生成。于是：
英雄从 x=340 一路走到 x=1352，交战点跟着往右漂 —— 挂久了战斗全挤在画面右侧。

## 同形态先行案例（桌面底部条挂机 RPG）

`guhcostan/deskbound-heroes`（MIT，Tauri + Phaser，受商业作品 TBH: Task Bar Hero 启发）
的战斗条截图里的构图是：

| 元素 | 位置 |
| --- | --- |
| 英雄（3 人小队） | 画面 **30%~40%**，朝右 |
| 怪 | 画面 **60%~70%**，**朝左**（从右边走进来，正在靠近/对峙） |
| 交战区 | 两者之间的 **画面中间** |
| 背景 | 分层：地面 → 前景植被 → 中景森林 → 远景雪山 |

它的架构也和我们一致：`src/sim/` 纯逻辑 + 全 Vitest 覆盖，Phaser 只负责画，Tauri 当壳。
**结论：我们照抄「英雄略偏左、怪从右边缘走进来、交战点在画面中间」这个构图**，比例取 45%。

## 落地

新增 `src/game/stage.ts`（纯函数，可单测）：

| 常量 | 值 | 为什么 |
| --- | --- | --- |
| `HERO_SCREEN_FRAC` | `0.45` | 英雄站画面 45%（略偏左，右边留给走进来的怪；怪最后停在 45%~60% 之间 = 中间） |
| `ENEMY_SPAWN_MARGIN` | `36` | 怪从画面右边缘往里 36px 进场（留在画面内，肉眼看得见它「走进来」） |
| `ENEMY_SPAWN_SPREAD` | `70` | 同一波横向错开，别叠在一起进场 |
| `TRAVEL_DISTANCE` | `300` | 超过这个距离算「赶路」 |
| `TRAVEL_MULT` / `MIN_TRAVEL_SPEED` | `4.5` / `200` | 见下（**必须**有，否则挂机干等） |

改动点：

- `ai.ts`：新增 `AiContext.holdPost` —— 英雄**不推图也不追人**（没目标不推、够不着不追），怪会自己走过来；
  追赶分支加 `travelSpeed(unit.speed, dist)`（只在远处生效，近了回自己的速度）。
- `main.ts`：新增 `pinHeroes()` + `viewportW()`，每帧把英雄摆回桩位（**开机也钉一次**，
  否则第一帧前英雄还在场景 json 的 x=340 = 画面 13% 处，会闪一下再跳到中间）。
  以场景里第一个英雄为桩，其他人保持相对间距（法师自然站在后面 90px）。
  刷怪点改用 `enemySpawnX()`；`advance: false, holdPost: true`。
- `public/scenes/chapter-1.json`：原来两块石头在 x=2430/2500 —— 正堵在新的右侧进场车道上，挪到 640/780（英雄左边）。

## 为什么必须有「赶路速度」（这是本次最关键的一条）

d2 那边给的移动速度是 **远程 30 / 近战 52~70 px/s**。从画面右边缘（x≈2524）走到中间（x≈1152）是 1372px：

| 速度 | 走完要多久 |
| --- | --- |
| 原地 52 px/s | **26 秒** |
| 原地 30 px/s | **46 秒** |

挂机屏上「26 秒没动静」看着就是卡住了 —— 这也正是当初把生成点塞在英雄前方 380px 的原因（代码注释里写着「挂机会干等」）。
现在改成：**距离 > 300px 用进场速度**（`max(速度×4.5, 200)`），进入 300px 后回自己的速度。

改完的实测：近战 1372/234 ≈ **5.9 秒**、远程 1372/200 ≈ **6.9 秒**（单测里钉死「必须 <10s / <12s」）。

## 自检（真机断言，不是看图）

`DESK_COMBAT_CHECK` 的采样里加了两个画面比例，写进判据：

```
构图：英雄在画面 45.0%~52.6%（桩位 45%，追远程怪时会往右一段） / 怪最靠右到 98.6%
波次推进：2 波（期望 ≥2：一波清完才会开下一波）
战斗自检：通过（英雄活动范围合理=true 回到过桩位=true 怪从右侧进场=true 波次推进=true）
```

- `heroFrac` 全程落在 **42%~62%**（出去追远程怪、回来后仍在中间，不漂到右边）
- **回到过 47% 以内**（证明打完会走回桩位，不是单向漂移）
- `enemyFracMax > 85%`（证明怪真的从右边缘进场，而不是半路冒出来）
- `wave >= 2`（证明「这一波清完才开下一波」真的在推进，卡住就到不了 2）

单测：`src/game/stage.test.ts`（站位比例 / 换窗口宽度仍居中 / 进场点在右边缘 / 错开 / 不越界 / 赶路速度的倍数与下限 / 走完 <10s）
+ `combat.test.ts` 新增 8 条（holdPost 不追不推、远程怪必须追、近战怪守桩不动、走回桩位、「出去—回来」可重复、远处快近处慢、旧行为不变）。

## 补充：远程怪与「守桩」的关系（真踩过）

用户报「怪物有远程攻击的，人物就走过去攻击，打死后，再继续放下一波怪物出来」——
根因是上一版**每帧把英雄 x 钉在桩位上**：远程怪（射程 220）停下开火、英雄站着够不着 → 这一波永远清不完 → 下一波也开不出来（游戏实际停摆）。
修法：**每帧只更新桩位坐标，不钉住位置**；`holdPost` 只对**近战**怪生效（它们会走过来），
**对面是远程怪就追**（`outranged`）；场上没敌人时走回桩位 —— 出去/回来都可重复，交战点仍围绕画面中间。
