# 数值接入：d2 关卡表 → 挂机战斗（d2-bridge）

> 原则：**d2 的知识只存在于一个文件** —— `src/game/d2-bridge.ts`。
> 其余内核文件（`units / ai / combat / waves / main`）不认识 d2，只认单位与事件。

## 数据流

```
src/lib/d2/campaign.ts   关卡表（12 章 × 10 关 × 4 难度）
        │  getStage(chapter, stage, difficulty) → StageMonster
        ▼
src/game/d2-bridge.ts    ★唯一换算层★
        │  enemyFromMonster() → EnemySpec（血量/防御/mlvl/TC/picks/noDrop/uber/MF 参数）
        │  heroStats(character) → 生命/伤害/命中/防御/攻速
        │  heroStrike() / monsterStrike() → 命中率 + 致命一击 + 元素伤害的掷骰
        │  rollLoot() → Item[]（TC 抽 + ItemRatio 定品质）
        │  stageLabelFor() / oddsFor() → HUD 文案
        ▼
src/game/main.ts       装配 + 主循环：把上面的结果塞进单位/HUD，击杀时结算掉落
```

## 波次 = 关卡

第 N 波直接映射到 d2 的关卡推进（每章 10 关）：

| 波次 | 章节/关卡 | 难度 | 说明 |
| --- | --- | --- | --- |
| 1–10 | 第 1 章 1-1～1-10 | 普通 | 1-5 精英怪、1-10 首领（`monsterKindForStage`） |
| 11–30 | 第 2–3 章 | 普通 | |
| 31–60 | 第 4–6 章 | 精英 | noDrop 42→24、picks 1、extraPickChance 45 |
| 61–90 | 第 7–9 章 | 噩梦 | picks 2、uber 开 |
| 91–120 | 第 10–12 章 | 地狱 | picks 3、tcBias 6、血量 ×15 |

难度是按章节给的（`difficultyForChapter`），不是按波次手调 —— 想让后期更硬就调 `src/lib/d2/campaign.ts` 的 `DIFFICULTIES`。

## 数值对照

| 游戏里的东西 | 来自 d2 的哪一项 |
| --- | --- |
| 英雄生命 | `characterLife(character)` = 40 + 等级×2 + 体力×3 + 装备 life |
| 英雄伤害 | `weaponDamageInputs()`（武器基础 + ED + 属性 + 元素）× 致命一击期望 = `averagePacket()` |
| 英雄命中 | `characterAttackRating()`（敏捷×5-7 + AR 词条） |
| 英雄防御 | `characterDefense()`（敏捷/4 + 装备防御） |
| 攻速 | `weaponDamageInputs().aps`（由 `attackFrames` 按武器基础帧数 + EIAS 算） |
| MF | `totalAttributes().stats.magicFind`（叠加在装备上） |
| 怪的血/防御/等级 | `StageMonster.hp / defense / mlvl` |
| 怪的伤害 | 关卡表**没有**这一项 → 按 `4 + mlvl×0.35` 推，精英 ×1.5、首领 ×2.2 |
| 掉落件数 | `StageMonster.picks`（难度给的抽签次数），每抽先过 `noDrop`（百分比） |
| 掉落品质 | `generateItem()` 走 TC + `quality.ts` 的 unique/rare/magic 几率，吃 MF 与 uber |
| 金币 | `StageMonster.gold` × 0.85~1.15 抖动 |
| HUD 掉率 | `farm.ts` 的 `stageOdds()`（和点击版工坊同一套数字） |

## 命中与伤害怎么走

`ai.ts` 每次攻击前问 `ctx.rolls`：

- 英雄挥砍 → `heroStrike()` → `swing()`：先判命中（AR vs 怪防御，5%~95%），命中再掷伤害包（物理 + 火/冰/电/毒 + 致命一击 ×2）
- 怪打英雄 → `monsterStrike()`：`chanceToHit(怪AR=mlvl×5, 英雄防御)`，**英雄防御高就真的会被闪开**
- 挥空有表现：`slash` 特效带 `params.miss = 1`，不结算伤害
- `rolls` 不传时退回单位的固定伤害（单测/降级路径）

## 击杀 → 掉落

`ai.ts` 把本帧死亡的实体放进 `AiResult.killed`，主程序逐个 `settleKill()`：

```
rollLoot(rng, unit.spec, magicFind) → { items, gold, noDrop }
  → lootCount[item.quality]++（HUD 计数）
  → lootBag.push(item)（上限 400 件，下一步做拾取/背包用）
  → lastDrop = { 稀有度中文 + 名字, 品质配色 }
```

随机数只有一个 `Rng`（`newRng(SEED)`，种子固定 20261002）——**自检才可复现**。

## 改东西该去哪

| 想改什么 | 改哪 |
| --- | --- |
| 怪多硬、掉多少件、掉率档位 | `src/lib/d2/campaign.ts` 的 `DIFFICULTIES` |
| 词条/品质/TC 规则 | `src/lib/d2/` 对应文件（`quality.ts` / `generate.ts` / `bases.ts`） |
| 波次 ↔ 关卡的映射、怪的名字/伤害推法 | `src/game/d2-bridge.ts` |
| 敌人进场位置、英雄用哪套装备 | `src/game/main.ts` |
| 一波刷几个、歇多久 | `src/game/waves.ts` 的 `WAVE_RULES` |

## 自检

```bash
npx vitest run src/game/d2-bridge.test.ts    # 17 条：映射/数值/掷骰/掉落确定性
DESK_COMBAT_CHECK=40000 npm run desk         # 真机：击杀、掉落件数、金币、关卡、零报错
```

`DESK_COMBAT_CHECK` 的通过线包含 `maxLootBag >= 1 && gold > 0` —— **掉落没发生就是失败**，防止"能打但不掉东西"这种静默退化。
