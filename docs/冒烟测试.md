# 冒烟测试（改完功能跑这一个）

```
npm run smoke                 全部 12 项（静态 4 + 真窗口 8），约 90 秒
npm run smoke -- --fast       只跑静态 4 项，约 12 秒（改完先跑这个）
npm run smoke -- --only=拖动   只跑名字里含「拖动」的项
npm run smoke -- --list       列出有哪些项
```

**判定一律看子进程出口码**（每个探针自己 `app.exit(0/1)`），不去 grep 日志文字 —— 文字会改，出口码不会。
有一项失败就以非零码退出，所以人和子代理都能拿它当验收门。每项完整输出落 `temp/smoke/*.log`。

已经有就直接用（不打扰正在看的那条）。没有 bash 会明确提示（窗口项靠 `VAR=值 命令` 注入环境变量）。

## 加一个功能时怎么做

1. **先写单元测试**：能纯函数化的逻辑就别只靠真机探针。参考两条现成的路：
   - 无 DOM 的：`src/game/debug.test.ts`（假 window 收 keydown 监听）
   - 需要 canvas 的：`src/game/render/renderer.test.ts`（用 Proxy 假造 2D context，把每个绘制调用记下来）
2. **再加一项真机探针**（如果功能涉及窗口/渲染/时序）：在 `electron/main.cjs` 里加一个新的 `DESK_*_CHECK` 分支，自己 `app.exit(0/1)`。
3. **把它挂进矩阵**：在 `scripts/smoke.mjs` 的 `CHECKS` 数组里加一行（`name` 用功能名，方便 `--only=` 挑）。
4. 跑 `npm run smoke`；全绿再交。

## 两个坑（踩过）

- **别用 `shell: true` 跑窗口项**：Windows 上它走 cmd.exe，`DESK_SMOKE=1 npm run desk` 这种 bash 语法会报
  「不是内部或外部命令」。`scripts/smoke.mjs` 里显式 `spawnSync(BASH, ["-c", cmd])`，没有 bash 就明确 SKIP。
- **测试别依赖「创建顺序」**：写渲染测试时我按「第 0 个渐变是天空、第 3 个是地面」取样例，
  结果远山是**纯色填充**不建渐变，索引整体错位，测试自己先红了。改成**按参数匹配**
  （`createLinearGradient(0,0,0,h)` = 天空、`(0,groundY,0,h)` = 地面）就稳了。
