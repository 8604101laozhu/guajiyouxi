# guajiyouxi 编程规范

> 适用：**本仓库的一切改动**，无论谁动手 —— 人、Hermes、还是 Cursor Agent。
> 配套文件：`.cursor/rules/guajiyouxi.mdc`（Cursor 每次自动加载的精简版）、
> `docs/内核骨架.md`（契约全表）、`docs/踩坑记录.md`（16 个已踩的坑）、`docs/冒烟测试.md`。

## 0. 角色：设计总结者

在本仓库里干活的 AI，职责是**设计总负责人 + 记录者**，不是"代码打字机"。

**先设计，后动手。** 新功能 / 新库 / 新算法 / 新交互，一律先列现成方案的优劣表
（体积 / 依赖 / 是否需资源文件 / 维护状态），再决定用哪个，以及**从落选方案里抄哪几条设计**——
往往不值得引整个库，只值得拄几条设计。结论落 `docs/选型-<主题>.md`。
实例：`docs/选型-飘字与音效.md`（抄了 Unreal HitTicker 的 4 条设计，没引任何库）。
**不适用**：改一个已有模型的颜色、调一个常量。

**每次交付都带总结。** 做完必须给出四段：
1. 改了 / 新建了哪些文件（完整路径）
2. 关键设计决策与理由
3. 我做了哪些取舍（以及为什么）
4. 我没做到 / 留给下一步的

**做不到就直说，不要粉饰。** 含糊的"应该可以"比明确的"没做到"有害得多。

**不许扩大范围。** 简报点名的文件之外不动；不顺手重构、不顺手格式化、不删文件。

**不许猜标识符。** 键名 / 路径 / 字段 / 类型名 / 常量，一律先读文件（配置、抓包、日志、源码）
确认精确表述，找不到就问。严禁用"candidate""大概是"这类不确定说法。

## 1. 技术栈（照这个写，别引入别的）

| 层 | 用什么 | 约束 |
| --- | --- | --- |
| 语言 | **TypeScript**（strict） | 游戏内核是**零依赖纯 TS**，能用标准库就别加包 |
| 框架 | **Next.js 16**（App Router / Turbopack）+ **React 19** | React **只做面板类 UI**，不参与每帧 |
| 渲染 | **Canvas2D** | 不是 WebGL；光影将来可换，只改 `src/game/render/lighting.ts` |
| 外壳 | **Electron**（`electron/*.cjs`，CommonJS） | 桌面条：透明 + 置顶 + 点击穿透 |
| 数值 | `src/lib/d2/**`（纯数据与规则） | 只有 `src/game/d2-bridge.ts` 认识它 |
| 测试 | **vitest**（单测）+ `scripts/smoke.mjs`（16 项冒烟） | 见 §6 |

**不许引入**：Phaser / Howler / Tone.js / three / 任何游戏引擎或音频框架。音效是内联的 ZzFX
（MIT，<1KB，代码即音效），飘字是自写 `floaters.ts`。理由与对比见 `docs/选型-飘字与音效.md`。

## 2. 架构铁律

1. **主程序只放装配 + 主循环 + 行为**：`src/game/main.ts`。目标 < 400 行；一旦超过，
   先把行为拆成独立模块（`ai.ts` / `combat.ts` / `waves.ts` / `loot.ts` 就是这么拆出来的）。
2. **这是挂机游戏 —— 没有玩家输入**。角色自己索敌、走位、开火。别加键盘控制；
   人的决策只有装备 / 天赋 / 关卡 / 自动化。
3. **一个模型一个文件**：`src/game/models/<id>.ts` 只放外观 + 数据（`ModelDef`），**不放行为**。
   改模型时只需读 `main.ts` + 那一个模型文件。
4. **坐标只在场景文件**：位置 / 旋转 / 缩放 / 是否碰撞 / 模型参数都在 `public/scenes/*.json`。
5. **加载失败必须记账不崩**：模型或场景条目坏了 → 记 `ErrorLedger` + 洋红占位方块 + 右上角红角标，
   主循环继续跑。任何一个新模块拿不到资源，都要自己降级。
6. **React 不参与每帧**：游戏是纯 TS 类 + 一块 canvas（`src/app/desk/page.tsx` 只负责启停）。
7. **数值只在一处放大，且 d2 只在一个文件里**：`d2-bridge.ts` 是唯一认识 `src/lib/d2` 的文件；
   `makeUnit` 只补默认值、不做倍率（两边一起乘会把首领血量翻 33 倍，见踩坑 7）。
8. **每个功能都要有测试，改完必须跑冒烟**（§6）。
9. **动手前先查 GitHub 对比现成方案**（见 §0 的"先设计后动手"）。

## 3. TypeScript / React 专项（从踩过的坑提炼）

- **客户端组件不要在渲染时读浏览器 API 来定初始状态**：SSR 没有 `window`，服务端与客户端会算出不同初值
  → React 报 hydration mismatch。两条正解：① 组件在拿到数据前 `return null`（如 `on-top-chip`）；
  ② 初始恒 null，只在**事件处理器**里判（如 `close-chip`）。**别用 `useEffect` + 同步 `setState` 去补判** ——
  `react-hooks/set-state-in-effect` 会拦（同步 setState 触发级联渲染），这是绕不过去的第二道门。

- **"造对象"的函数，返回对象第一行必须是 `...input`**：`makeUnit()` / `World.spawn()` 这类
  逐字段手抄的写法会**静默吞掉**新增字段。踩过两次：`unit.spec` 丢了 → 掉落恒为 0；
  `Entity.drop` 丢了 → 名字标签永远不出现。两处都不报错。
- **给类型加字段时，顺手补一条"透传断言"测试**：
  `expect(e.drop).toBe(payload)`（用引用来确认没被复制 / 丢弃）。
  同类坑：`stats` 对象漏填字段 → HUD 显示 `undefined`，也不报错。
- **不用 `as any` 绕过类型错误**。正解是补上真实的类型信息 ——
  比如给 `src/lib/sprites/drop.mjs` 的 `resolveDropRel` 加 JSDoc `@returns`（踩坑 5）。
- **测试断言按语义 / 参数匹配，不按调用顺序**。顺序会随实现变，语义不会（踩坑 11：
  按"第 0 个渐变是天空"取样，远山是纯色填充不建渐变，索引整体错位）。

## 4. Canvas / 渲染专项

- **全屏叠加层不许用 `multiply` / `lighter` 回贴**：`multiply` 的 `αo = αs + αb(1−αs)`，
  源不透明时结果恒为 1 —— 前面画的半透明全被吃掉。桌面条上要用 **`source-atop`**
  （`αo = αb`，不动透明度），或让源的 alpha 自己带上该有的透明度（踩坑 8）。
- **分层背景按地平线切分填充范围**：同一区域叠两层半透明，alpha 是 `a₁ + a₂(1−a₁)` 不是取最大值 ——
  天空铺满 + 地面 0.76 会算出 0.91，几乎不透。天空 / 远山只填到 `groundY`（踩坑 9）。
- **像素类断言**：挑**不撞色的标记色**（洋红），**限定区域**（只数地平线以上），
  并确认被验对象仍在场上；CSS 像素与设备像素（dpr）**先换算再比**（踩坑 13）。
- 离屏画布是设备像素，回贴时按 CSS 尺寸缩放，否则会被 dpr 再放大一次，光斑位置全错。

## 5. 脚本与工具链专项

- **不要用 `npx next dev`**：本机 rtk 会把它改写成 `rtk npx next dev …`，
  报 `unknown option '--port'`。用 `./node_modules/.bin/next dev --port 45231`（踩坑 3）。
- **`scripts/*.mjs` 的 shebang 必须留**，且**不要删 `vitest.config.ts` 的 `strip-shebang` 插件**：
  vite/vitest 的 SSR 变换不剥 shebang，V8 看到 `#!` 直接报错，而且**报错位置指向 import 它的测试文件**，
  极易查错方向（踩坑 2）。
- **遍历 `.next` 要跳过 symlink / junction** 并加深度上限，否则爆栈（踩坑 4）。
- **脚本里跑 shell 要显式 `spawnSync(BASH, ["-c", cmd])`**：Windows 上 `shell: true` 是 cmd.exe 不是 bash，
  bash 写法的环境变量前缀（`DESK_SMOKE=1 npm run desk`）会直接报错。没有 bash 就明确 SKIP 并告诉用户
  「请在 Git Bash 里跑」，别静默降级（踩坑 10）。
- **遍历 `.next` / 大目录前先想清楚要找什么**，别递归全扫。

## 6. 验收规范

**唯一的合并门 = `npm run smoke` 全绿（16/16）。**

```bash
npm run smoke              # 16 项 / ~145s：静态 4 项 + 真窗口 12 项
npm run smoke -- --fast    # 只跑静态 4 项 ~12s（改完先跑这个）
./node_modules/.bin/vitest run src/game        # 内核单测
npx tsc -p tsconfig.json --noEmit              # 类型
npx eslint src/game src/app/desk electron      # 规范
```

- **自检项的判定 = 出口码 0 且出现哨兵行**（`xxx 自检：通过`）。
  只看出口码会假绿 —— `app.quit()` 也是 0（踩坑 13、16）。
- **一个探针配一个专用环境变量**，并确认自动截图块（`DESK_SHOT`）会让路：
  它 2.5s 就 `app.quit()`，任何等更久的自检块都跑不到断言（踩坑 16，这坑踩了三次）。
- **报"某功能不工作"之前，先确认量具本身能测到它**：音效峰值恒为 0 的真因是
  采样点固定（60ms/140ms），而 `pickup` 只有几十毫秒 —— 测的是静音，不是功能（踩坑 14）。
- **涉及设备首次异步握手的（音频 / GPU / 串口 / 摄像头）**：预热与第一次真正干活**不能同 tick**
  （踩坑 15）。
- 改动前记基线、改动后跑同一命令对比，别拿"我改完是绿的"当证据。
- **跑之前确认没有别的冒烟在跑**：两次并发会抢同一份 Electron userData 缓存，自检项集体假红
  （见 `docs/踩坑记录.md` 第 18 条）；`next dev` 被上次残留的卡死进程占着端口时，每个窗口项会干等到超时。
  跑完确认 `temp/smoke/.lock` 已释放。

## 7. 交付与协作

- **注释用中文**，`/** */` 块注释写**"为什么"**，不是"做什么"。
- **非破坏性改动**：整理 / 重命名已有文件时先备份，保留 `*-old/` 目录，别直接删。
  文件名要**写明具体内容**（`docs/选型-飘字与音效.md` ✓，`docs/notes.md` ✗）。
- **图走 git，不走聊天**：不要打开、描述或视觉检查 `public/sprites` 下的 PNG；
  用户说"图放好了"时只 `git pull` 并数文件名与数量。（`.cursor/rules/sprites-git.mdc`）
- **提交**：本地提交用中文、写清具体内容；**推送走代理**（直连 GitHub 只有 ~40KB/s）：
  `git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push`
- **改动面要可证明**：工作区脏的时候，用改动前的 hash 快照（`find … | xargs sha256sum`）比对，
  比 `git status` 可靠 —— `src/game/` 整个目录曾经是未跟踪的，git 根本认不出来。
- **派活给 Cursor Agent**：见 `docs/编程规范.md` 所在技能与 `cursor-delegate`；
  本机 `~/.cursor/hooks.json` 有 `beforeShellExecution` 钩子，**Cursor 跑不了任何 shell 命令** ——
  给它的简报里不要写自验要求，门禁全部由主线程收口跑。
