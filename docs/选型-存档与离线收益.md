# 选型：存档 + 离线收益

用户要求：「看一下 GitHub 上的挂机游戏项目，再优化一下」。
挂机游戏最典型的两个缺失就是**进度不落盘**（重载归零）和**离线不给收益** —— 我们两样都没有。
这一轮就补这两件。

## 先看开源同类怎么做

| 项目 | 做法 | 我们抄什么 |
| --- | --- | --- |
| **guhcostan/deskbound-heroes**（和我们同形态：桌面底部条闲 RPG，Tauri + Phaser + 纯 `src/sim`） | `storage.ts`：一个 localStorage key；`saveGame` 把 **`now: Date.now()` 直接打进存档**；`loadGame` 里版本不符就**从头开始**；`migrateGame` **逐字段 `?? 默认值`** 兜新增字段；**离线时长上限是解锁项**（`unlocks.offlineMinutes`，默认 20 分钟）；离线收益 = `applyOfflineProgress(state)` | ① `now` 进存档 ② 逐字段 `?? 默认` 的迁移 ③ 上限先固定 20 分钟（将来做成解锁项） |
| **blixxurd/clicker-engine** | `applyOfflineProgress(state, registries, lastSaveTime, now)` **纯函数**；`parseWithMigrationInfo` 返回「是否迁移过」 | 离线计算做成**纯函数**（好测）；迁移要给调用方一个 `migrated` 标志 |
| **MattGibney/Epoch-Foundry** | 自动存档 **每 10 秒 + 页面退出/隐藏各一次**；IndexedDB + schema 版本；离线收益「capped, with upgrade extensions」 | 存档时机：定时 + `pagehide`/`visibilitychange` |
| **idlekitjs/idlekit** | autosave / offline 是**可插拔策略**；核心与 DOM 无关；`SaveAdapter` 契约（内存 / localStorage） | 存储做成适配器接口（可注入内存实现）→ 测试不需要浏览器 |
| **simonfruehauf/OpenIdle-Engine** | localStorage 自动存档 + 存档导出成 Base64 分享 | 暂不做（记在这，将来加「导出/导入存档」按钮） |
| **decimal.js / break_infinity**（大数库） | 处理天文数字 | **不需要**：我们数值走 d2，量级到不了 JS 浮点精度边界 |

## 落地设计

三个模块，全是纯逻辑 / 可注入依赖，因此都能单测：

| 文件 | 职责 | 关键点 |
| --- | --- | --- |
| `src/game/save.ts` | 存档结构 + 序列化 + 校验 + 迁移 | **不认识 d2**（`items` 只声明成 `unknown[]`，守住「d2 只在一个文件里」）；任何字段坏了就夹到合法值，**永不 throw**；版本比程序新 → 拒绝读（不猜） |
| `src/game/offline.ts` | 离线收益纯计算 | `nowMs < savedAtMs`（时钟被改回去）→ 0，**绝不给负奖励**；上限 20 分钟、速率上限 2000 金/分（防存档被改出天文数字） |
| `src/game/save-store.ts` | 唯一碰 localStorage 的地方 | localStorage 不可用（隐私模式/磁盘满）→ 退回内存实现，**游戏照跑只是不落盘**（本工程铁律） |

接线（`main.ts`）：
- 开局读一次：进度（**波次/累计击杀/金币/战利品袋/药水槽**）留下来；`waves` 的计时器保持全新，让它正常开下一波。
- 离线收益按**上次会话实测的速率**（`goldPerMinute` / `killsPerMinute`，跟存档一起存）结算；没有速率（老存档/第一次）就算 0 —— **不编造奖励**。
- 落盘：每 **10 秒**一次 + `pagehide` / `visibilitychange(hidden)` + `stop()` 时各一次。
- 「欢迎回来」：弹提示条（复用调试提示条，连弹 3 次）+ 英雄头顶飘一笔金币。

## 自检的两个前提（踩过的坑）

1. **探针必须从干净状态开始**：冒烟的所有窗口项现在带 `DESK_FRESH=1`（URL 上加 `?fresh=1` 忽略存档）。
   否则上一项留下的存档会污染下一项 —— 比如战斗自检可能从"第 7 波"开始。
2. **离线自检反过来，需要种存档**：`DESK_OFFLINE_CHECK=1` 先在页面里塞一份「3 小时前」的存档再重载，
   断言：值得报 / 真实离开 180 分 / 被上限截断成 20 分 / 补发金额 = 速率×上限 / 进度还原 / `persist()` 真写进去了 / 零报错，
   跑完**清掉存档**不污染后续项。

## 明确不做（记下来免得以后重复讨论）

- **离线期间不结算装备掉落**：只补金币和击杀数。理由：装备掉落要走 d2 的 TC/ItemRatio 掷骰，
  离线几十分钟会刷出一大袋装备，还要考虑「离线掉落怎么展示」；先做小、做可解释的部分。
- **不做大数库**：数值来自 d2，量级可控。
- **不做存档导出/导入**（Base64）：现在只是单机自用，等有分享需求再加。
