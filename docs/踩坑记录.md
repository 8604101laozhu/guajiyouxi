# 已知坑（踩过并已修）

## 1. `next dev` 不带代理 → 所有页面 500

`src/app/layout.tsx` 原来用 `next/font/google` 拉 Noto Serif SC + Geist Mono，本机到 `fonts.googleapis.com / fonts.gstatic.com` 会超时，导致**每个页面**（包括 `/desk`）500，报 `Can't resolve '@vercel/turbopack-next/internal/font/google/font'`。

**已修**：字体改成自托管 —— `public/fonts/` + `src/app/fonts.css`，不再请求外网。
想换字重/加字体：挂代理跑一次 `next dev` 把新字体下到 `.next`，再 `npm run selfhost:fonts` 重新固化。

自查脚本：`temp/font-probe.cjs`（`DEV_URL=… electron temp/font-probe.cjs`），会打印 `externalFontReqs`（应为 `[]`）和 `document.fonts` 的加载状态。

## 2. vitest 里 import `scripts/*.mjs` 报 `SyntaxError: Invalid or unexpected token`

`scripts/*.mjs` 第一行是 shebang（`#!/usr/bin/env node`）。node 和 esbuild 都会剥掉它，**vite/vitest 的 SSR 变换不会**，于是 V8 看到 `#!` 直接报错，而且**报错位置指向 import 它的那个测试文件**（`x.test.ts:2:1`），很容易查错方向。

**已修**：`vitest.config.ts` 加了一个 `strip-shebang` 插件（`enforce: "pre"`）。不要删——以后任何新加的 `scripts/*.mjs` 都靠它。

## 3. `npx next dev` 在本机 bash 里会被 rtk 包一层

表现为 `error: unknown option '--port'`（命令被改写成 `rtk npx next dev …`）。
**绕法**：直接用本地二进制 `./node_modules/.bin/next dev --port 45231`。

## 4. `.next` 里有 symlink/junction，递归扫描会爆栈

`scripts/selfhost-fonts.mjs` 第一版在 `.next` 里递归找 woff2，`RangeError: Maximum call stack size exceeded`。
**规矩**：任何遍历 `.next` 的脚本都要 `entry.isSymbolicLink() → continue`，并跳过 `node_modules` / `cache`，加深度上限。

## 5. `npm run build` 曾被一个类型错误挡住

`src/lib/sprites/drop.test.ts` 读 `resolveDropRel(...)?.destName`，但 `scripts`→`src/lib/sprites/drop.mjs` 的返回类型被收窄成没有 `destName` 的那一支（只有背景命中才带这个字段）。
**已修**：在 `src/lib/sprites/drop.mjs` 的 `resolveDropRel` 上加了 JSDoc `@returns`（`destName?: string`）。别在测试里加 `as any` 绕过去。

## 6. 造单位时逐字段手抄 → 扩展字段静默丢失（掉落恒为 0）

`makeUnit()` 原来是一个字段一个字段抄进返回对象。接 d2 之后给 `Unit` 加了 `spec / defense / mlvl`，**它们全被丢掉了**，而且不报错：

- `unit.spec` 丢了 → 击杀结算拿不到掉落参数 → **掉落永远是 0**，HUD 上只看到"击杀 8 / 掉落 0"；
- `unit.defense` 丢了 → 命中率判定退化成"防御 0"，怪几乎打不中英雄、英雄几乎必中，d2 的命中公式等于没接上。

**规矩**：`makeUnit` 返回对象第一行必须是 `...spec`，字段默认值写在后面覆盖。给 `Unit` 加新字段时，顺手补一条"透传断言"测试（见 `combat.test.ts` 的"扩展字段必须透传"）。
同类坑：`stats` 对象字段漏填 → HUD 显示 `undefined`，也不报错。

## 7. 数值不要两处各乘一次

`makeUnit` 原来自己按 `rank` 放大血量/伤害（精英 ×2.4、首领 ×6），而 d2 的关卡表**已经**按 `kind` 放大过（首领 ×5.5）。两边一起乘 → 首领血量 33 倍，挂机直接卡死。
**规矩**：数值只在一处放大。现在唯一的来源是 `src/lib/d2`（关卡表），`makeUnit` 只补默认值、不做任何倍率。

## 8. `multiply` 合成会把半透明背景一次糊成不透明

光影 Pass 原来用一块**不透明的**环境色画布以 `multiply` 回贴主画布。`multiply` 的 alpha 是 `αo = αs + αb(1−αs)`，源不透明（`αs=1`）时结果恒为 1 —— 前面画的半透明全被吃掉（实测画布 alpha 全 255）。
**规矩**：桌面条上的任何全屏叠加层都不能用 `multiply`/`lighter` 回贴（它们都会抬 alpha）。要么用 **`source-atop`**（`αo = αb`，不动透明度），要么让源的 alpha 自己带上该有的透明度。

## 9. 半透明图层叠两层 = 接近不透明

同一块区域被两层半透明覆盖时，alpha 是 `a₁ + a₂(1−a₁)`，**不是**取最大值。天空铺满整块画布 + 地面 0.76 → `0.62 + 0.76×0.38 = 0.91`，地面几乎不透（实测 232/255）；远山填到画布底部也犯同一个错。
**规矩**：分层背景要按地平线切分填充范围（天空/远山只到 `groundY`），改完用 `DESK_ALPHA_CHECK=1` 量每一带的 alpha，别靠眼睛猜。

## 10. Windows 上 `shell: true` 是 cmd.exe，不是 bash

冒烟脚本第一版用 `spawnSync(cmd, { shell: true })` 跑窗口项，于是 `DESK_SMOKE=1 npm run desk` 这种 bash 写法直接报「'DESK_SMOKE' 不是内部或外部命令」——8 项全红。而 `./node_modules/.bin/electron` 在 cmd 里同样跑不了。
**规矩**：脚本里显式 `spawnSync(BASH, ["-c", cmd])`，没有 bash 就明确 SKIP 并告诉用户「请在 Git Bash 里跑」，别静默降级。

## 11. 测试别依赖「创建顺序」

写渲染测试时按「第 0 个渐变是天空、1-2 是远山、3 是地面」取样例，但**远山是纯色填充、根本不建渐变**，索引整体错位，4 条断言自己先红（而且看起来像功能坏了）。
**规矩**：断言按**语义/参数**匹配（`createLinearGradient(0,0,0,h)` 就是天空），不按调用顺序；顺序会随实现变，语义不会。

## 12. 造实体的函数也会吞字段（`World.spawn`）

`World.spawn()` 原来把 entity 逐字段抄出来，于是新增的 `Entity.drop`（掉落物载荷）被静默吞掉：掉落图标照画、名字标签永远不出现、**不报错**。写代码的人靠"spawn 之后再手挂 `e.drop = …`"绕过去，坑被推迟但没修。
**规矩**：`spawn` / `makeUnit` 这类"造对象"的函数，返回对象第一行必须是 `...input`；给类型加字段时补一条"透传断言"测试（`expect(e.drop).toBe(payload)`，比引用来确认没被复制/丢掉）。

## 13. 自检的"假绿"比没测更危险

同一个进程里多个自检块 + 只看出口码，会造出一串假通过，这轮连中三次：

- `DESK_LOOT_CHECK` 与 `DESK_SHOT` 同用 → SHOT 块 2.5s 就截图并 `app.quit()`，断言压根没跑，**退出码还是 0**。
- 探针把 CSS 像素和设备像素（dpr 1.5）混着比，`238 <= 309` 恰好成立 → 假通过。
- "数某个颜色出现没有"用了青色，撞上法师弹道（835 像素横跨 1800px）→ 数的根本不是标签。

**规矩**：① 冒烟项判定 = 出口码 0 **且**出现哨兵行（`xxx 自检：通过`）；② 一个探针配一个专用环境变量，别和别的自检块抢退出；③ 像素类断言要挑"不撞色的标记色"（洋红）、要限定区域（只数地平线以上）、还要确认被验对象仍在场上；④ 单位统一（CSS vs device 像素先换算再比）。

## 14. 「功能坏了」有一半是量具坏了

音效第一声真机实测峰值恒为 0，我先顺着"冷启动吃掉第一声"的解释去改预热 —— 改了两轮还是 0。真相是**峰值采样方式漏掉了短音效**：`pickup` 只有几十毫秒，而采样点是固定的 60ms/140ms，声音早结束了，采到的是静音。
**规矩**：报"某功能不工作"之前，先确认量具本身能测到它。修法：测存续期连续采样（16ms 一次 + 尾巴 60ms），别用固定几个时间点。

## 15. 冷启动：预热和第一次真正干活不能同 tick

`AudioContext.resume()` 是异步的。同一个 tick 里 `start()` 会被设备初始化吃掉（真机第一声真的哑）。修法两条一起：预热等 `resume()` 落地后再做（`.then(warmUp)`），且「预热」与「放第一声」错开一个 tick（`WARMUP_DELAY_MS = 80`）。**再配上开机预热**（`main.ts` 建好就 `unlock()`，挂机条没人点，不能等交互）。
同类场景：任何"设备/驱动首次初始化"的异步握手（音频、GPU、串口、摄像头）都适用。

## 16. `DESK_SHOT` 抢跑是个复发坑（第三次踩）

`DESK_SHOT` 的自动截图块在 2.5s 就 `app.quit()`，任何等更久的自检块都跑不到断言；而且**退出码是 0**（假绿）。
这轮飘字探针又中了一次。规矩：**一个探针一个专用环境变量**，并且自动截图块要显式让路（`if (SHOT && !LOOT_INJECT && !FLOAT_CHECK)`）。新增自检块时，先问一句"它会不会被别的块的退出打断"。

## 17. 客户端组件在渲染时读浏览器 API → hydration mismatch

`CloseChip` 最初照抄 `OnTopChip` 的惰性初始化：
`useState(() => typeof api()?.close === "function" ? null : "需重启条")`。
SSR 时没有 `window` → 算出来是「需重启条」；客户端 hydration 时通道在 → 算成 `null`。
两边 `title` / `className` 不一致，React 直接报 hydration mismatch（冒烟窗口日志里抓到的）。
`OnTopChip` 用同样写法却没事，只因它在拿到状态前 `return null`、整个组件不渲染，差异藏住了。

**规矩**：客户端组件不要用浏览器 API 定**初始状态**。两条正解：① 拿到数据前 `return null`；
② 初始恒 `null`，只在**事件处理器**里判。**别用 `useEffect` 补判** —— `react-hooks/set-state-in-effect`
会拦住（同步 setState 触发级联渲染），这是绕不过去的第二道门。

## 18. 两个冒烟同时跑 → 自检假红

并发跑两次 `npm run smoke`（或上一次的进程没退干净），两次会抢同一份 Electron userData 缓存。
表现：`置顶开关` 自检 7 个指标全 false（`按记忆启动` / `关得掉` / `开得回` / `按钮跟着翻` /
`偏好落盘` / `被顶掉能补回`），看着像功能坏了，其实是量具坏了。
清掉残留进程、单独重跑，**同样的代码 17/17 全绿**。

**规矩**：跑之前确认没有别的冒烟在跑（`Get-Process` 看 `node scripts/smoke.mjs`），
跑完确认 `temp/smoke/.lock` 已释放；遇到「一堆自检项同时假红」先怀疑并发，别急着改代码。
同一条：`next dev` 也会被上一次留下的**卡死进程**占着端口 —— 症状是每个窗口项干等到超时，
先杀干净再跑。

## 19. `cmd start` 的窗口标题必须带引号

`scripts/smoke.mjs` 自起 dev server 那行原来是
`spawnSync("cmd", ["/c", "start", "/min", "guajiyouxi-smoke", "cmd", "/c", …])`。
`start` 的语法是「**只有带引号的第一个参数**才算窗口标题」，少了这对引号，它就去找一个叫
`guajiyouxi-smoke` 的**文件** —— 找不到就弹「Windows 找不到文件『guajiyouxi-smoke』」，
dev 服务器压根起不来，后面所有窗口项直接跳过。

**为什么潜伏很久没暴露**：`ensureServer()` 只在没有现成 dev server 时才走到这条分支，
平时复用已起的服务永远碰不到它（顺带说明：这条分支几乎没被跑过，等于没测）。

**规矩**：标题参数写成 `'"guajiyouxi-smoke"'`（JS 里用单引号包一对双引号，免转义）。
修完实测：杀掉 dev server 后跑 `npm run smoke`，服务自己起来了（45231 LISTENING）且不再弹窗。
