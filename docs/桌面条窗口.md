# 桌面条窗口（桌面壳）

窗口是由 `electron/main.cjs` 建的：整屏宽 × 260 高（`DESK_HEIGHT` 可改）、透明、无边框、置顶、不占任务栏、**按住直接拖（或长按 0.35s 再拖）**、位置会记住。

## 操作

| 操作 | 作用 |
| --- | --- |
| **按住直接拖**（或长按 0.35 秒再拖） | 搬动整条：按下后位移 < 6px 就松手算点击、不搬窗；松手放下，`Esc` 取消 |
| `Ctrl+Alt+S` | 复位回屏幕底部居中 |
| `Ctrl+Alt+D` | 点击穿透（鼠标直接穿过去干活） |
| `Ctrl+Alt+T` | 置顶开关 |
| `Ctrl+Alt+R` | 重载页面 |
| `Ctrl+Alt+Q` | 退出 |

## 拖动是怎么实现的（以及为什么不那样做）

**不用的方案**：`app-region: drag`（Electron 官方"自定义可拖拽区域"）。
它只在矩形 DOM 区域生效、会**吞掉该区域的点击**（游戏画面全设成 drag 就没法点游戏了），而且已知在 devtools 打开时失效、透明窗口下拖动/最大化异常。

**用的方案**（按住即拖 / 长按 + 主进程轮询光标 + 工作区夹取）：

```
页面 use-long-press-drag.ts          electron/main.cjs                    electron/drag.cjs
  pointerdown ─350ms 不动─┐
                          └─→ window.deskBar.dragStart() ──ipc──→ 记录 起始窗口位置 + 当前光标
                                                                        ↓ setInterval(16ms)
                                              每一帧：win.setPosition(clamp(起始位置 + 光标位移))
  pointerup / Esc / 失焦 ──→ dragEnd() ──ipc──→ 停表 + 位置落盘
```

三个关键决定，各有理由：

1. **光标由主进程读**（`screen.getCursorScreenPoint()`），不看页面的 `mousemove`：窗口自己在动，DOM 坐标会跟着一起漂，越拖越飘；鼠标划出窗口边界 DOM 就收不到事件了，而系统光标一直读得到。桌宠类应用都这么做。
2. **位置夹进显示器工作区**（`screen.getDisplayNearestPoint().workArea`）：拖出屏幕也拉得回来。这正是 Deskrawl 的做法（它的 `TransparentWindow` 用 `MonitorFromWindow/GetMonitorInfo` 拿 `rcWork` 夹取）。
3. **长按才拖**（350ms，抖动超过 6px 就不算）：拖动和"点游戏"共用同一个画面，没有这个门槛就会误触。

Deskrawl 是在画面右下角挂了个**可见拖拽柄**（`GameAnchorDragHandle`，实现 `IBeginDragHandler/IDragHandler/IEndDragHandler`，并订阅 `GameState` 决定什么时候可用）；我们整条都是游戏画面，所以改成"长按任意处"，更省 UI 空间。

## 位置记忆

拖过之后（位移 > 2px）写 `%APPDATA%\guajiyouxi\desk-window.json`，下次启动夹回工作区后用这个位置；没拖过就贴底居中。
`DESK_FORGET_POS=1` 可以忽略记忆从底部开始。

## 自检

```bash
# 1. 拖窗数学 + 控制器（假窗口，不需要 Electron）
npx vitest run src/game/desk-shell.test.ts

# 2. 真实窗口：脚本化光标，验 follow / 夹取 / 松手不跟手
./node_modules/.bin/electron temp/drag-probe.cjs

# 3. 全链路冒烟：模拟长按 → 拖动 → 松手，并截一张"拖动中"的图
DESK_SMOKE=1 DESK_DRAG_FIXED_CURSOR="600,900" DESK_SMOKE_SHOT=temp/desk-dragging.png npm run desk
```

`DESK_DRAG_FIXED_CURSOR` 是给自检用的：不设的话拖动会跟着真实鼠标跑，测不出稳定结果。
